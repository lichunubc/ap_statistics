# Authoring and preserving the course

## Start from the current repository

Read `_quarto.yml`, `project/topic-status.json`, and the existing adjacent chapters before editing. Preserve existing URLs and user changes. Commit source files, never only generated HTML. Refresh the branch immediately before a write; reconcile concurrent changes and never force-push.

## One topic, one coherent learning progression

Use `templates/topic.qmd` as an outline. Each topic needs explicit learning targets mapped to the current College Board CED, an introduction, well-labelled examples, purposeful interactions, common misconceptions, original practice and worked answers. Keep extensions separate. Do not label uncreated topics as completed. Topic IDs and CED editions belong in metadata, not just prose.

Use Maple Hill School / Chun Li branding, consistent notation, and plain-language context. Typeset mathematics with LaTeX in QMD; Quarto renders it to MathML. The categorical School A sample (40 students) is separate from the quantitative commute sample (24 students). Preserve counts and explain when an example changes datasets.

## Reusable assets

- QMD files at the project root are the editorial source. Keep current paths stable.
- `assets/` contains reusable JS/CSS and any original diagrams; use system fonts.
- `data/` contains original/synthetic datasets and source/provenance notes.
- `tools/` contains reproducible preview and validation scripts.
- `project/` stores curriculum mapping, release state and the development roadmap.
- `templates/` stores editable authoring templates.
- `docs/` is generated by the verified publishing workflow; do not edit it by hand.

Keep original data where exact values are known. Do not invent raw observations from histogram bins. Mark simulated, synthetic, classroom and published data clearly. Attribute external sources next to their use and maintain their licensing conditions; a public link is not a redistribution licence.

## Student privacy and rights

No real student records, credentials, private teacher notes, secure AP Classroom questions or restricted assessments belong in this public site. Create original formative questions. Link public official exam documents instead of uploading their full PDFs. Do not distribute font files. Do not introduce analytics, accounts, paid services or persistent learner tracking without separate authorization.

## Accessibility and correctness

Controls must have labels and keyboard access. Answers start unselected; clear/next reset both selection and feedback. Give non-colour cues, graph descriptions, print reference states, and reduced-motion support. Static explanations and written answers must remain useful without JavaScript. Never claim an exact value that a grouped graph does not reveal.

## Validate and release

1. Check arithmetic and dataset totals independently.
2. Run `quarto render` (the pinned CI version is in `.github/workflows/publish.yml`).
3. Run `python tools/check_site.py` and `python tools/check_foundations.py` with the test requirements installed. Add tests for new components.
4. Inspect desktop and mobile renders, math, links, quizzes, and printing.
5. Commit the source and update `CHANGELOG.md` and `project/topic-status.json`.
6. Inspect the GitHub Actions build and **Publish site** step; a successful build alone is not a deployed site. Check the live chapter separately and report any validation limitation honestly.

The portable `python tools/preview.py` route uses Pandoc and the current chapter list. It is useful offline but does not replace checking the genuine Quarto build in CI.
